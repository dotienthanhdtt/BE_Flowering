# Brainstorm — Auto-Generate Personalized Scenarios (Premium Plus + Premium Upsell)

**Date:** 2026-05-04
**Status:** Design — pending approval
**Author:** dotienthanhdtt

---

## 1. Problem Statement

Premium Plus users should receive personalized practice scenarios generated by AI based on their interests, profession, and goals — delivered as a "gift" experience triggered by completing curated scenarios. Premium users get one free trial per month to drive upsell to Plus.

The flow mirrors the existing **anonymous onboarding** pattern: AI runs a multi-turn intake conversation, extracts structured user info, then generates 5 personalized scenarios. Difference: this is authenticated, tier-gated, repeatable, and persists scenarios into the real `scenario` library (not anonymous JSON cache).

## 2. Requirements

### Functional
- Trigger: completing a scenario flagged `triggersPersonalization=true` fires intake chat (gift UX).
- Intake AI: reuses existing onboarding profile + asks deltas for **interests, profession/daily life, goals/motivation**.
- Output: 5 new scenarios per generation, accumulate in user library (soft cap 30, prune oldest unused).
- Tier gating:
  - **Premium Plus**: unlimited generations.
  - **Premium**: 1 free trial per calendar month, paywall mid-flow at extraction step.
  - **Free**: blocked entirely (no trigger fires).
- De-dup gate: **skip generation** if last fire <24h ago AND extracted profile has no new fields vs. previous fire.
- Persistence: new scenarios written to existing `scenario` table with `ownerUserId` + `source='personalized'`.

### Non-Functional
- LLM cost predictability — de-dup + monthly cap on Premium prevent runaway spend.
- Reuse onboarding infra (`UnifiedLLMService`, `PromptLoaderService`, `AiConversation`) — no parallel stack.
- Response latency: intake reply <3s p95; final generation <8s p95 (matches onboarding).
- Idempotency: trigger event firing twice (e.g., retry) must not double-generate.

## 4. Approaches Evaluated

### Approach A — "Mirror Onboarding" (Standalone Module)
Build a new `personalization` module that mirrors `OnboardingService` pattern almost verbatim.

**Pros:** Fast to ship, low risk of breaking onboarding, easy to reason about.
**Cons:** ~70% code duplication; 2 places to fix bugs; drift over time.

### Approach B — "Extract Shared Intake Engine" (Recommended)
Refactor onboarding's chat/extract loop into a generic `IntakeChatEngine` that takes:
- `promptKey` (system prompt to load)
- `extractionPromptKey`
- `maxTurns`
- `conversationType`
- `onComplete(profile, conversationId) → T` callback (where T = scenarios for both flows)

Both `OnboardingService` and new `PersonalizationService` become thin wrappers.

**Pros:** DRY; one place to fix prompt-parsing bugs; extensible (future: pronunciation intake, etc.).
**Cons:** Refactor adds ~1 phase of work; touches a tested onboarding flow (regression risk — mitigated by existing onboarding tests).

### Approach C — "Inline in Onboarding Module"
Add `personalization` endpoints inside `OnboardingModule`, sharing the service.

**Pros:** Minimal new files.
**Cons:** Conceptually wrong — onboarding is anonymous, this is authed. Coupling tier logic into onboarding pollutes a clean module. Rejected.

**→ Recommendation: Approach B** unless time-pressure forces A. The intake-engine extraction is small (~150 LoC) and pays back across two flows immediately.

## 5. Recommended Architecture

### 5.1 Data Model Changes

**`scenario` entity**
```
+ ownerUserId: uuid | null      // null = global; non-null = personalized
+ source: enum('default','kol','personalized')   // already exists, formalize enum
+ INDEX (ownerUserId, source, createdAt DESC)
+ triggersPersonalization: bool default false    // admin-flagged "gift trigger"
```

**`user` entity**
```
+ personalizedTrialUsedAt: timestamp | null      // Premium upsell quota; reset monthly via cron OR computed (current month vs stored month)
+ lastPersonalizationAt: timestamp | null        // for 24h de-dup gate
+ personalizationProfileSnapshot: jsonb | null   // last extracted profile, for diff-based de-dup
```

**`access-tier.enum`**
```
FREE = 'free'
PREMIUM = 'premium'
PREMIUM_PLUS = 'premium_plus'   // NEW
```

**`AiConversationType`**
```
+ PERSONALIZE_INTAKE
```

### 5.2 Module Layout

```
src/modules/personalization/
├── dto/
│   ├── personalize-chat.dto.ts
│   └── personalize-complete.dto.ts
├── services/
│   ├── intake-chat-engine.service.ts          # SHARED with onboarding (Approach B)
│   ├── personalization.service.ts
│   ├── personalization-quota.service.ts       # Premium 1/month; Plus unlimited
│   └── personalization-trigger.service.ts     # called when scenario completed w/ flag
├── personalization.controller.ts              # POST /personalization/chat, /complete
└── personalization.module.ts
```

`OnboardingService` refactored to use `IntakeChatEngine`.

### 5.3 Trigger Flow (Gift UX)

```
[user completes scenario]
      ↓
ScenarioChatService.onComplete()
      ↓
PersonalizationTriggerService.maybeTrigger(userId, scenarioId)
      ├─ scenario.triggersPersonalization === true ?
      ├─ user tier check → Plus: pass | Premium: quota check | Free: drop
      ├─ 24h de-dup check  →  if recent + no new info expected → drop
      └─ if pass → emit `PersonalizationOfferedEvent` (push notification + in-app banner)
                  ↓
            user opens chat → POST /personalization/chat
                  ↓
            multi-turn intake (5 turns max)
                  ↓
            POST /personalization/complete
                  ├─ extract profile (LLM)
                  ├─ DIFF vs personalizationProfileSnapshot
                  ├─ if no new fields AND lastPersonalizationAt < 24h → return existing scenarios, no new generation
                  ├─ else: generate 5 scenarios → INSERT into scenario table w/ ownerUserId
                  ├─ update lastPersonalizationAt + profileSnapshot
                  ├─ if Premium: set personalizedTrialUsedAt
                  └─ prune to soft cap (30 oldest unused personalized)
```

### 5.4 Quota & Paywall (Premium Upsell)

- Premium can **start** the chat freely (no friction → high engagement).
- At `/personalization/complete`, check quota:
  - Plus → proceed.
  - Premium with no trial used this month → proceed, mark `personalizedTrialUsedAt`.
  - Premium with trial used → **return paywall response** (`code: 0, message: 'upgrade_required', data: { upsellTo: 'premium_plus' }`). Mobile shows upgrade modal. Conversation persists so they can resume after upgrade.
- Quota window = calendar month based on user TZ (or UTC for v1 — simpler).

### 5.5 De-Dup Gate (Critical for Cost Control)

Two cumulative conditions to **skip** new generation:
1. `now - lastPersonalizationAt < 24h`, AND
2. Extracted profile has no fields not present in `personalizationProfileSnapshot` (set diff on top-level keys + value-equality).

If skipped: return last batch of personalized scenarios + a friendly message ("Your scenarios are still fresh — check back tomorrow"). LLM tokens for extraction are still spent (~512 tokens), but the expensive 1024-token scenario generation is skipped. Acceptable trade.

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Trigger spam → cost explosion | 24h+no-new-info de-dup gate (user-approved); add hard ceiling (e.g., max 3 generations/day even for Plus) as safety net |
| Race condition on rapid double-trigger | Trigger service uses Postgres advisory lock on `userId` for the trigger-check critical section |
| Profile snapshot diff misses semantic changes (same keys, new values) | v1 uses value-equality; if too strict, relax to "key-set diff only"; revisit after telemetry |
| LLM produces near-duplicate scenarios across batches | Pass last 10 scenario titles into generation prompt as "avoid duplicating these" |
| Premium user starts chat, hits paywall, abandons | Persist conversation; show resume CTA after upgrade. Track funnel: trigger → start → complete → upgrade |
| `triggersPersonalization` flag forgotten on new admin scenarios | Default `false`; admin UI toast when bundle has 0 trigger scenarios |
| Soft-cap pruning deletes scenarios user actually liked | Only prune scenarios with 0 chat sessions (never-used); favorites are sticky |
| Tier migration breaks existing Premium users | DB migration leaves all current `premium` rows untouched; PREMIUM_PLUS only via explicit RevenueCat product mapping |

## 7. API Surface

```
POST /personalization/chat
  body: { conversationId?, message? }
  response: { conversationId, reply, messageId, turnNumber, isLastTurn }

POST /personalization/complete
  body: { conversationId }
  response (success): { scenarios: ScenarioPersonalDto[], generatedNew: bool, quotaRemaining?: number }
  response (paywall): { code: 0, message: 'upgrade_required', data: { upsellTo: 'premium_plus', conversationId } }

GET /personalization/messages?conversationId=...
  (mirror onboarding /messages for resume)
```

Existing `GET /scenarios?source=personalized` already lists personalized scenarios; just needs to filter by `ownerUserId === currentUser`.

## 8. Implementation Phases (Preview — full plan via /ck:plan)

1. **Schema + tier**: migrations for `scenario.ownerUserId/triggersPersonalization`, `user.personalized*`, `AccessTier.PREMIUM_PLUS`, `AiConversationType.PERSONALIZE_INTAKE`.
2. **Refactor onboarding → IntakeChatEngine** (Approach B). Verify onboarding tests still pass.
3. **Personalization module**: service, controller, prompts, DTOs.
4. **Trigger service + scenario-completion hook**: wire into `scenario-chat` completion flow.
5. **Quota + paywall response logic** for Premium tier.
6. **De-dup gate** + profile snapshot diff.
7. **Pruning cron / soft cap** (lazy: prune-on-insert).
8. **Tests**: unit (each service), integration (full trigger→generate path), e2e (mocked LLM).
9. **Mobile contract** (separate plan in `app_flowering`).
10. **Langfuse tagging** for new features (`PERSONALIZATION_CHAT`, `PERSONALIZATION_EXTRACTION`, `PERSONALIZATION_SCENARIOS`).

## 9. Success Metrics

- **Activation**: % of Plus users who complete ≥1 trigger scenario in first 14 days.
- **Engagement**: avg generations/Plus user/month; avg personalized-scenario chat sessions.
- **Upsell**: Premium → Plus conversion rate within 7 days of hitting paywall.
- **Cost**: avg LLM cost / personalization session (target <$0.40); de-dup skip rate (target >20%).
- **Quality**: % of personalized scenarios with ≥1 chat session (proxy for relevance).
